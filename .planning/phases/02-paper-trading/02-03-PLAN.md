# Plan 02-03: Trailing Stop Implementation (PAPER-03)

## Objective

Fix the trailing stop order execution to properly track peak prices and trigger stops based on price retreat from the peak, not current price fluctuation.

## Background

Current issues identified in research:
1. `checkTrailingStop()` in order-manager.ts (lines 277-313) doesn't track highest/lowest price since order creation
2. The logic checks current price vs trailing %, not peak price retreat
3. Engine integration code is commented out (lines 562-570 in paper-trading-engine.ts)
4. `PaperPosition` already has `highestPrice`/`lowestPrice` but they're not being used for trailing stops

### Correct Trailing Stop Logic

For a LONG position with 5% trailing stop:
1. Entry at $100, initial stop at $95 (5% below entry)
2. Price rises to $110, stop adjusts to $104.50 (5% below new high)
3. Price drops to $104, stop stays at $104.50 (no adjustment down)
4. Price drops to $104.50 or below: TRIGGER stop loss

The stop should ONLY move in the favorable direction (up for longs, down for shorts).

Also update the stopPrice only when the peak improves:
```typescript
updateTrailingStop(orderId: string, highPrice: number, lowPrice: number): void {
  const order = this.orders.get(orderId);
  if (!order || order.type !== "TRAILING_STOP") return;

  if (order.side === "SELL") {
    // Update peak (highest price seen)
    const newPeak = Math.max(order.peakPrice ?? 0, highPrice);
    if (newPeak > (order.peakPrice ?? 0)) {
      order.peakPrice = newPeak;
      // Recalculate stop price based on new peak
      if (order.trailingPercent) {
        order.stopPrice = newPeak * (1 - order.trailingPercent / 100);
      } else if (order.trailingAmount) {
        order.stopPrice = newPeak - order.trailingAmount;
      }
    }
  }
  // Similar for BUY orders with lowPrice
}
```
