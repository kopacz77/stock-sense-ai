    Create `scripts/m201-build-recommendation.ts` (or `src/scripts/m201-build-recommendation.ts` matching Plan 05's convention).

    **Input:** `.planning/phases/07-strategy-reality-check/results.jsonl`
    **Output:** `.planning/phases/07-strategy-reality-check/RECOMMENDATION.md`

    **Step 1: Load and parse JSONL**
    Read line by line, skip empty/malformed lines, skip records with `.error` field (errored backtests). Parse each into a typed record matching the schema from Plan 05.

    **Step 2: Apply per-(ticker × strategy × params) pass logic**
    For each record, compute per-regime pass:
    - `bullPass = regimeMetrics.bull.sharpeRatio > 0.5 && Math.abs(regimeMetrics.bull.maxDrawdown) < 25`
    - `bearPass = regimeMetrics.bear.sharpeRatio > 0.5 && Math.abs(regimeMetrics.bear.maxDrawdown) < 25`
    - `highVolPass = regimeMetrics.highVol.sharpeRatio > 0.5 && Math.abs(regimeMetrics.highVol.maxDrawdown) < 25`
    - `regimesPassed = [bullPass, bearPass, highVolPass].filter(Boolean).length`
    - `anyRegimeMaxDDover35 = ['bull','bear','highVol'].some(r => Math.abs(regimeMetrics[r].maxDrawdown) > 35)`
    - `negativeBullSharpe = regimeMetrics.bull.sharpeRatio < 0`

    Apply CONTEXT.md verdict per record:
    - `verdict = anyRegimeMaxDDover35 || negativeBullSharpe ? 'DISCARD' : (regimesPassed === 3 ? 'KEEP' : (regimesPassed === 2 ? 'MODIFY' : 'DISCARD'))`

    Also compute:
    - `lowTradeFlag = tradesPerYear < 10`  // RESEARCH pitfall #6 — buy-and-hold proxy

    **Note on maxDrawdown sign:** per RESEARCH pitfall #8, `maxDrawdown` is signed negative (e.g., -18.5 means 18.5% drawdown). Always `Math.abs()` before threshold comparison. Add a code comment about this — this is the #1 sign-flip footgun.

    **Step 3: Aggregate per (strategy × params) across universe**
    For each strategy × params combination, compute across all tickers:
    - `medianSharpe.{bull,bear,highVol}` (use a small median helper, or sort+pick middle)
    - `medianMaxDD.{bull,bear,highVol}` (also median of absolute values; report as positive for readability)
    - `tickersPassing.{bull,bear,highVol}`: count of tickers where that regime passed
    - `keepCount`: number of tickers where verdict was KEEP
    - `modifyCount`, `discardCount`
    - `lowTradeCount`: tickers flagged as buy-and-hold proxy

    Build a list keyed by `${strategy}|${JSON.stringify(params)}` → aggregate.

    **Step 4: Determine strategy-level verdict**
    For each strategy (`momentum`, `meanReversion`), use the **best-performing param set** (the one with the highest `keepCount`, then highest median bull Sharpe as tiebreak) as the "representative config." The strategy-level verdict is the verdict from that representative config's aggregated medians:
    - Strategy KEEP: median Sharpe >0.5 AND median |MaxDD| <25% in all 3 regimes, across the best config's universe runs.
    - Strategy MODIFY: passes in 2/3 regimes AND no regime median |MaxDD| >35%.
    - Strategy DISCARD: fails ≥2 regimes OR any regime median |MaxDD| >35% OR negative median bull Sharpe.

    Note: this is a more permissive bar than per-ticker because it lets a strategy "pass" if its best config works across the *median* of the universe even if some tickers fail. This matches the CONTEXT.md intent ("does the strategy have edge") rather than "does it work on every ticker."

    **Step 5: Generate RECOMMENDATION.md**

    - Tickers passing all 3 regimes: <N>/35

    | Bear | X.XX | -XX.X% | N/35 | Sharpe >0.5 AND MaxDD <25% |
    | High-Vol | X.XX | -XX.X% | N/35 | Sharpe >0.5 AND MaxDD <25% |

    ### Top 5 tickers (KEEP across all 3 regimes)
    [list with per-regime Sharpe / MaxDD]
