## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator CLI args → engine + file writes | `--date`, `--types`, `--max-candidates`, `--ticker` reach file reads, the engine and candidate persistence |
| Signal modules (LLM-derived inputs) → ranked, sized output | Four independent modules' scores compete to occupy a real position slot |
| `config/strategy-config.json` → sizing and ranking | A hand-edited config directly controls dollar exposure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-05-01 | Elevation of Privilege | Shadow candidate reaching the ranked, sized list | high | mitigate | Shadow signals bypass ranking and sizing structurally (partitioned before `rankCandidates` is called), `suggestedSizeUsd` is forced `null`, and both are asserted including a case where a shadow candidate outscores every core candidate |
| T-11-05-02 | Tampering | `config/strategy-config.json` edited to an unsafe `scoreFloor`, `maxCandidatesPerDay` or `regimeSizePct` | high | mitigate | `loadStrategyConfig` (11-02) validates ranges and throws naming the offending key; this plan adds the `signalModes`-vs-module-mode consistency assertion so a config edit cannot silently promote a shadow type |
| T-11-05-03 | Tampering | `--types` / `--date` / `--ticker` CLI input | medium | mitigate | `--types` is validated against the `SignalType` union with `process.exit(2)`; dates are parsed and rejected when non-finite; `--ticker` is upper-cased and used only as a map key, never as a path segment |
| T-11-05-04 | Denial of Service | One failing signal module aborting the whole run | medium | mitigate | Per-module `try/catch` converts a throw into a `skippedTypes` entry so the other three types still produce candidates |
| T-11-05-05 | Repudiation | A candidate the operator acted on cannot be reconstructed | medium | mitigate | Every candidate including sub-threshold and shadow is persisted to `candidates-YYYY-MM-DD.jsonl` with its `candidateId`, score, levels and rationale before any decision is taken |
| T-11-05-06 | Information Disclosure | Rationale text (LLM-derived) printed to a terminal | low | accept | Single-operator local CLI; text is already on disk in `data/intel` |
| T-11-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero new packages. If an install becomes necessary, stop and run the Package Legitimacy Gate before adding it |
</threat_model>
